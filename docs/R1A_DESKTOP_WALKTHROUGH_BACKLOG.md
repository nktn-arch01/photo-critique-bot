## 1. コンセプトとの緊張（検討課題）

1. **「評価ではなく理解」 vs 表層の評価語彙**  
   Rating 0–4、カード ★5軸、出力フォルダ名「評価カード」。ブランド原則と見え方のすり合わせ（リネーム／コピー／説明 UI）。

2. **「答えではなく対話」 vs 長文講評が主成果**  
   痕跡はフル講評中心。「そう思う／違う」の短い反応ループ（速い輪）は未実装。

3. **北極星の「その日のうちに」vs 現行が週次深い輪のみ**  
   速い輪（R4′）後続。初回体験が選別寄りになるリスクの製品コミュニケーション。

4. **二アプリ・二ブランド名**  
   `Lumina Notes 短絡` と `Photo AI 講評` の役割分担を初心者向けに一本化／案内する。

5. **Rating 意味と DxO 星 UI の認知ギャップ**  
   1=M1合格、2=M2、3=余白、4=上位、0=除外。DxO の「出来の星」と異なることの説明・ヘルプ。

## 2. UX 不自然さ（検討課題）

1. アプリ → DxO → アプリの往復と Works 規約（`_dev.jpg`、RAW 非配置）の学習コスト  
2. 短絡のフォルダ名ゲート／直下 JPEG のみ  
3. 月一括時にイベント配下が黙って対象外  
4. Works フォルダ名が非 `YYYYMM` のときの `DesktopLogManager` 出力名（親に変な年次ログ）  
5. 短絡 GUI が API キー未検証のまま M2/M3 開始可能  
6. `_dev` 優先で撮って出しを黙ってスキップ（両方に痕跡を付けたい場合の UI なし）  
7. 「DxO修正後を記録」と痕跡生成の順序・必須感の整理

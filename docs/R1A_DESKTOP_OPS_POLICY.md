# デスクトップ運用方針（確定メモ）

更新日: 2026-08-11  
位置づけ: オーナー回答に基づく **運用・中優先改修の確定方針**。実装前の契約。  
関連: [`R1A_DESKTOP_WALKTHROUGH_BACKLOG.md`](R1A_DESKTOP_WALKTHROUGH_BACKLOG.md) / [`R1_DEEP_LOOP_SPEC.md`](R1_DEEP_LOOP_SPEC.md)

---

## 0. 一文で

- **オリジナル**はカメラ運用どおり `OM` 接頭辞を正式規則にする。  
- **Works** はユーザーが自作。アプリは生成もコピーもしない。  
- アプリは **短絡（Rating/説明）＋ DxO修正後の記録 ＋ Works 上の痕跡**だけを担う。

---

## 1. 維持する現行仕様（一度広げた案は撤回）

| 項目 | 方針 |
|------|------|
| Works イベント名 | **`YYYYMMDD_短い名前`** に揃える（日付8桁） |
| Works パス自動生成 | **しない**（ユーザーが自分で作る） |
| 短絡開始時の Works 生成 | **しない** |
| Works へのファイルコピー | **しない**（DxO / OS が手動） |
| H3 UI | **「DxO修正後を記録」のみ**（コピー機能を付けない） |
| 痕跡の年の取り方 | 対象フォルダ名の **先頭4文字を年**（`202606`→`2026`、`20260615_旅行`→`2026`） |

---

## 2. オリジナル・フォルダ規則（実運用を正式採用）

カメラや現像アプリが違っても、**この庫のオリジナル命名は統一**する。

| 単位 | 規則 | 例 |
|------|------|-----|
| 年ルート | `OM{YYYY}` | `~/OM2026` |
| 月 | `OM{YYYYMM}` | `~/OM2026/OM202606` |
| イベント | `OM{YYYYMM}_短い名前`（スペースなし） | `~/OM2026/OM202606/OM202606_旅行` |

- 接頭辞 **`OM` は必須**（他年・他カメラでも同じ）。  
- 短絡の対象は **個別指定**（月直下とイベント配下は別バッチ）。  
- 月バッチは直下 JPEG のみ（イベント配下は含めない）— 現行どおり。

**実装メモ:** 現行 `library_unit` は `YYYYMM` / `YYYYMMDD_名前` のみ。  
→ 短絡受付を **`OMYYYYMM` / `OMYYYYMM_名前` に拡張する改修が必要**（別タスク。中優先 M1–M5 より上流）。

---

## 3. Works 側のパス（ユーザー作成・アプリ非生成）

推奨レイアウト（ユーザーが作る）:

```text
~/{YYYY}/{YYYYMM}/                     # 例: ~/2026/202606
~/{YYYY}/{YYYYMM}/{YYYYMMDD_名前}/     # 例: ~/2026/202606/20260615_旅行
```

- オリジナル `OM202606` に対応する Works 月は `202606`（`OM` なし）。  
- Works イベントは **必ず `YYYYMMDD_`**（オリジナルの `OMYYYYMM_名前` とは形が違ってよい。対応はユーザーが管理）。  
- RAW は置かない。確定は Rating 3/4 の `_dev.jpg`（なければ撮って出し `.jpg`）。

---

## 4. アプリ責務の境界

| ゾーン | やること | やらないこと |
|--------|----------|--------------|
| **短絡** | M1–M3、監査、`DxO修正後を記録` | Works 生成、ファイルコピー、現像 |
| **痕跡** | Works 上の JPEG にカード／ノート／ログ | コピー、短絡の再実行必須化 |
| **DxO / OS** | Rating 修正、現像、Works へ手動配置 | — |

アプリ分割: **当面は1アプリ・2ゾーン**（短絡＋記録／痕跡）。コピーを持たないので、痕跡専用アプリ必須ではない。

---

## 5. 「DxO修正後を記録」のタイミング（日またぎ現像）

- ボタンは **記録のみ**（オリジナル JPEG の Rating/説明を再スキャン → `post_h3` / `h3_delta`）。  
- **何度押してもよい**（現像途中の日でも可。最新スナップショットとして更新）。  
- Works へのコピーは **別作業（手動）**。記録ボタンの成否と独立。  
- 短絡作業を閉じるとき、未記録なら確認してよい（任意の UX。コピーは聞かない）。  
- 痕跡は **Works に実ファイルがあるとき**に実施。

---

## 6. 痕跡ログ配置（M1 確定）

| 成果物 | 保存先 |
|--------|--------|
| 写真分析ノート・評価カード・月別ログ・処理ステータス | **Works の当該フォルダ内**（月またはイベント） |
| 年別写真分析ログ | **Works の年フォルダ** `~/{YYYY}/写真分析ログ_{YYYY}.txt` |

例:

```text
~/2026/202606/
  202606写真分析ノート/
  202606評価カード/
  202606写真分析ログ.txt
  202606処理ステータス.txt

~/2026/写真分析ログ_2026.txt          ← 年次（月フォルダの親＝年）

~/2026/202606/20260615_旅行/
  20260615_旅行写真分析ノート/
  …（月次相当はイベント配下）

~/2026/写真分析ログ_2026.txt          ← イベント痕跡も同じ年次へ集約
```

### 年の決定

- **年番号** = 対象フォルダ名の先頭4文字（数字の `YYYY` であること）。  
  - `202606` → `2026`  
  - `20260615_旅行` → `2026`

### 年次ファイルの置き場所（実装上の注意）

現行 `DesktopLogManager` は「直親ディレクトリ」に年次を書く。  
イベントが `…/2026/202606/20260615_旅行` のとき直親は月フォルダになり、**意図する `…/2026/` とずれる**。

**M1 実装方針:**

1. 年番号はフォルダ名先頭4文字（契約どおり）。  
2. 年次ログの親は「直親」固定ではなく、**年フォルダ（名前がその `YYYY` の祖先、または明示指定）**へ置く。  
3. 月フォルダ `…/2026/202606` では結果的に直親＝年フォルダで現行と同じ見た目になる。

## 7. 中優先改修への落とし込み

| ID | 方針（この確定後） |
|----|-------------------|
| **M1** | 上記 §6。年次は年フォルダへ。先頭4文字で年を取る。Works 自動生成・コピーは対象外 |
| **M2** | 「DxO修正後を記録」は **target 配下セッションのみ**を正とする |
| **M3** | 開始時に Tk 変数をスナップショットしてワーカーへ渡す |
| **M4** | 記録処理をワーカースレッド化（固まり防止）。コピー UI は作らない |
| **M5** | `card_theme` / `force_overwrite` は共有のまま文書化 |

### 中優先より先（または並行）で必要な別タスク

| ID | 内容 |
|----|------|
| **P1** | `library_unit` / 短絡 GUI が `OMYYYYMM`・`OMYYYYMM_名前` を受け付ける |

P1 なしだと、実運用オリジナルパスで短絡を開始できない。

---

## 8. やらないこと（この方針での再確認）

- Works フォルダの自動作成  
- Works へのアプリによるファイルコピー／移動  
- 「記録・コピー」一本化ボタン  
- オリジナル側イベント名を無理に `YYYYMMDD_` へ強制（オリジナルは `OMYYYYMM_名前`）

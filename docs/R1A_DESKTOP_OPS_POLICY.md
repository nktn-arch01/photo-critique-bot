## 0. 一文で

- **オリジナル**は機種別2文字接頭辞＋日付の統一規則（下記 §2）。  
- **Works** はユーザー自作で **月フォルダ `YYYYMM` のみ**（イベントサブフォルダは作らない）。  
- アプリは **スクリーニング（Rating/説明）＋ 終了時の H3 自動記録 ＋ 任意のスクリーニング「カード」＋ Works 月フォルダ上の痕跡**だけを担う。Works へのファイル生成・コピーはしない。

---

## 1. 維持する現行仕様（一度広げた案は撤回）

| 項目 | 方針 |
|------|------|
| Works 構成 | **月 `YYYYMM` のみ**。イベント `YYYYMMDD_名前` は **作らない** |
| Works パス自動生成 | **しない**（ユーザーが自分で作る） |
| スクリーニング開始時の Works 生成 | **しない** |
| Works へのファイルコピー | **しない**（DxO / OS が手動） |
| H3 | **Console 終了時に自動記録**（手動ボタンなし。アプリ性能向上用データ。dry-run は対象外） |
| スクリーニング カード | Rating 3/4 に任意で Phase1 カード＋ Description へ TITLE 等（上書き ON/OFF） |
| Lumina Review の年の取り方 | Works 月フォルダ名の **先頭4文字を年**（`202606`→`2026`） |

## 2. オリジナル・フォルダ規則（正式）

文字位置の意味:

| 位置 | 意味 | 例 |
|------|------|-----|
| 1–2 | メーカー・機種コード `XX`（英大文字想定） | `OM`（OM SYSTEM）, `FF` など |
| 3–6 | 年 `YYYY` | `2026` |
| 7–8 | 月 `MM` | `06` |
| 9–10 | 日 `DD`（イベントのみ） | `15` |

フォルダ種別:

| 単位 | パターン | 例 |
|------|----------|-----|
| 年ルート | `XXYYYY` | `~/OM2026`, `~/FF2026` |
| 月 | `XXYYYYMM` | `~/OM2026/OM202606` |
| イベント | `XXYYYYMMDD_短い名前`（スペースなし） | `~/OM2026/OM202606/OM20260615_旅行` |

- `XX` は固定の1種類ではなく、**機種ごとに異なる2文字**を許す（同じ庫に `OM*` と `FF*` が混在してよい）。  
- スクリーニングの対象は **個別指定が基本**（月直下とイベント配下は別バッチ）。  
  Console では任意で「配下イベントも順に実行」できる（Wave B2）。H3 差分は **Console 終了時に未記録分を自動記録**（単位ごと。手動ボタンなし）。  
- 月バッチの既定は直下 JPEG のみ（イベント配下は含めない。上記オプション OFF 時）。

**Works 月との対応（運用）:** 接頭辞2文字を除いた `YYYYMM`。  
例: `OM202606` → Works `~/2026/202606`。イベント由来の確定コマも同じ月 Works へ集約。

**実装メモ（P1）:** `library_unit` は `XXYYYYMM` / `XXYYYYMMDD_名前`（`XX` = `[A-Za-z]{2}`）を正式受付。  
接頭辞なしの `YYYYMM` / `YYYYMMDD_名前` も後方互換で残す。`month_id` / `works_month_id` は常に暦の `YYYYMM`。

## 3. Works 側のパス（ユーザー作成・月のみ）

```text
~/{YYYY}/{YYYYMM}/          # 例: ~/2026/202606
  （イベント用サブフォルダは置かない）
  *.jpg / *_dev.jpg         # 月直下バラ＋イベント由来もここに集約
```

- オリジナル `OM202606` / `FF202606` および配下イベントの確定コマは、すべて対応 Works 月（接頭辞を除いた `YYYYMM`）へ手動配置。  
- RAW は置かない。確定は Rating 3/4 の `_dev.jpg`（なければ撮って出し `.jpg`）。  
- Lumina Review の対象フォルダは **常にこの月フォルダ**を選ぶ。

**シンプルになる点:** オリジナルのイベント単位と Works の月単位が分離され、「Works 側のイベント命名対応表」が不要になる。

## 4. アプリ責務の境界

| ゾーン | やること | やらないこと |
|--------|----------|--------------|
| **スクリーニング** | M1–M3、監査、終了時 H3 自動記録、任意「カード」生成（オリジナル月／イベント） | Works 生成、ファイルコピー、現像 |
| **Lumina Review** | Works **月**フォルダ上の JPEG にカード／ノート／ログ（Full【1〜7】）。埋め込み Phase1 があれば再利用 | コピー、イベント別 Works フォルダ |
| **DxO / OS** | Rating 修正、現像、Works 月フォルダへ手動配置 | — |

アプリ分割: **当面は1アプリ・2ゾーン**（スクリーニング＋記録／Lumina Review）。

---

## 5. H3 自動記録のタイミング（日またぎ現像）

- Console を閉じるとき、未記録のセッションへ **自動で** `post_h3` / `h3_delta` を書く（ユーザー作業ではない。アプリ改善用）。  
- dry-run（`write_meta=False`）セッションは対象外。  
- Works へのコピーは **別作業（手動）**。H3 成否と独立。  
- Lumina Review は **Works 月フォルダに実ファイルがあるとき**に実施。  
- スクリーニング「カード」は Rating 3/4 にいつでも実行可（上書き ON/OFF）。JPEG Description に Phase1 4項目を upsert。

## 6. Lumina Review ログ配置（M1・簡略化後）

| 成果物 | 保存先（公式名・Wave 2 以降） |
|--------|--------|
| Luminaノート・Luminaカード・月別ログ・処理ステータス | **Works 月フォルダ内** `~/{YYYY}/{YYYYMM}/` |
| 年別 Luminaログ | **Works 年フォルダ** `~/{YYYY}/Luminaログ_{YYYY}.txt` |

例（新規出力）:

```text
~/2026/202606/
  202606Luminaノート/
  202606Luminaカード/
  202606Luminaログ.txt
  202606処理ステータス.txt
  P614_dev.jpg …
~/2026/Luminaログ_2026.txt
```

### 移行期間（旧名フォールバック）

Wave 2 以降、**書き込みは常に上記の公式名**。既存 Works に残る旧名は **自動リネームしない**（ユーザー資産）。

| 旧名（読込のみ） | 公式名（書き込み） |
|------------------|-------------------|
| `{ym}写真分析ノート/` | `{ym}Luminaノート/` |
| `{ym}評価カード/` | `{ym}Luminaカード/` |
| `{ym}写真分析ログ.txt` | `{ym}Luminaログ.txt` |
| `写真分析ログ_{year}.txt` | `Luminaログ_{year}.txt` |

- **処理済み判定**（`is_processed`）と **既存ノート／カードの解決**は、新名 → 旧名の順で探索する。  
- 上書き再生成しても旧フォルダ内のファイルは消さない（新旧が並存しうる）。必要なら Finder で旧フォルダを手動整理。  
- 詳細棚卸し: [`R1A_NAMING_CLEANUP.md`](R1A_NAMING_CLEANUP.md) Wave 2。

### 年の決定・年次の置き場所

- 年番号 = 月フォルダ名の先頭4文字（`202606`→`2026`）。  
- 年次ファイルの親 = 月フォルダの直親（＝年フォルダ `2026`）。  

Works が月のみなら、現行 `DesktopLogManager`（`year_str = name[:4]`、年次＝`parent/`）が **このレイアウトと一致**する。  
→ **M1 の「祖先探索」改修は原則不要**。必要なら「Lumina Review 対象は `YYYYMM` 名のみ」の検証・案内を足す程度。

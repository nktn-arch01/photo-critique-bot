# R1′ 深い輪 機能仕様書

更新日: 2026-08-10  
親構想: [`LUMINA_NOTES_SERVICE_CONCEPT.md`](LUMINA_NOTES_SERVICE_CONCEPT.md)  
位置づけ: **実装前の機能仕様**。API 実装コードは含まない。第一波の詳細は **R1′-A**。  
短絡アルゴリズムの数値閾値・実装手法は実装段階で詳細化する。本仕様は段の目的・順序・禁止事項・入出力を固定する。

## 1. 目的と成功条件

### 1.1 目的

ミラーレス派ユーザー（当面はオーナー本人）が、**週次およびイベント単位**の写真群に対して、

1. **段階的な短絡**（機械選別 → Lumina アンテナ → 多様性調整、各所に人の回収）で取りこぼしを抑えつつ候補を整え、  
2. DxO 等で現像した JPEG（または撮って出し／JPEG 補正）をオリジナルとは別に **作品** として取り込み、  
3. 既存の Lumina Notes（カード・分析ログ）と紐づけて **対話痕跡** を残す  

ことで、あとから未来の自分が読み返せる素材を蓄積する。

北極星のうち、本仕様が担うのは主に **深い輪（あとからの振り返り）** 側である。  
中心にある往復（残す→見返す→言葉にする→もう一度見る）を、週／イベントの単位で回せるようにする。

### 1.2 縮約の目安（最終）

| 単位 | 入力の目安 | 確定の目安 |
|------|------------|------------|
| 週 | 約 200 枚 | 約 20 枚 |
| 月／イベント | 約 400 枚 | 約 40 枚 |

途中段の枚数目安は §6。比率はガイドであり、最終枚数は人が決める。

### 1.3 成功条件（R1′-A）

オーナーが、**週フォルダ（例: 約 200 枚）またはイベントフォルダ（例: 約 400 枚）** に対して次を日常操作として完了できる。

1. 段階短絡（M1→…→H3）が走り、各段の候補／除外が見える  
2. 特に機械除外からの回収（H1）ができる  
3. 確定分を Works へ **撮って出し＋RAW ペアコピー**し、`{stem}_dev.jpg`（または撮って出し）で対話痕跡を付けられる（週次もイベントも。オリジナル非破壊）  
4. 作品にカード／Markdown ノート／ログが紐づく  
5. 段ごと・セッション全体の DecisionDelta が後から参照できる

## 2. ユーザーストーリー

### US-1 週末の短絡と作品化

週末、ミラーレスで撮った週の写真（およそ 200 枚）を開く。機械選別→アンテナ→多様性の段階で候補が絞られ、途中で除外の回収もできる。およそ 20 枚に整えたら、同名の撮って出しと RAW を Works へコピーし、DxO 等で `{stem}_dev.jpg` を書き出してからカード／ログを紐づける。

### US-2 イベント後の短絡と作品化

旅行イベント `YYYYMMDD_短い名前` でも同じファネルとペアコピー／`_dev.jpg` 契約を使う（およそ 400→40）。

### US-3 言葉と痕跡

候補・作品の場面で、AI が言語化した文を見る。納得しなくても「そう思う／そうではない」と感じる。必要ならコメントやキーワードを足す。既存の講評カードと分析ノートが作品に紐づく。

### US-4 あとから読み返す準備

短絡の各段結果・作品・カード／ログ・差分が、同じ月／イベントの配下に残り、将来の章やレポート（R1′-B/C）の素材になる。

## 3. 対象範囲／非対象

### 3.1 スライス

| スライス | 状態 | 内容 |
|----------|------|------|
| **R1′-A** | **本仕様の詳細対象・第一波必須** | 段階短絡、人の確定／回収、週次・イベントの作品取り込み、カード／ログ、差分ログ |
| **R1′-B** | 境界のみ（§11） | 振り返り章（画面／PDF） |
| **R1′-C** | 境界のみ（§11） | 蓄積ログの外部分析用エクスポート（NotebookLM 等） |

### 3.2 R1′-A に含めないもの

- 毎日 20→1 の速い輪（R4′）
- クラウドアルバム入力（R5′）
- 自前 RAW 現像・アプリ内本格補正（外部現像成果の取り込みは含む）
- 印刷業者入稿
- 種写真からの自動ストーリー補完の本実装（R3′）
- **★絶対閾値（例: ★5必須）による自動最終選別**
- ブレ検出閾値・類似度アルゴリズム・情緒タグ語彙の確定（実装詳細）
- LINE／マルチユーザー／課金

## 5. ドメインモデル

### 5.1 LibraryUnit

| フィールド | 型・制約 | 説明 |
|------------|----------|------|
| `id` | 文字列 | 安定ID |
| `kind` | `month` \| `event` | 月またはイベント |
| `path` | 絶対パス | 対象フォルダ |
| `label` | 文字列 | 表示名。イベントは `_` 以降 |
| `ym` | `YYYYMM` | 所属月 |

フォルダ規則:

- 月: 親フォルダ名 `YYYYMM`
- イベント: `YYYYMMDD_短い名前`
- パターン不一致のサブフォルダはイベント単位にしない

### 5.2 SourceAsset

| フィールド | 説明 |
|------------|------|
| `path` / `file_name` | オリジナル |
| `captured_at` | EXIF `DateTimeOriginal` 優先（`scanner.py`） |
| `suffix` | `SUPPORTED_IMAGE_SUFFIXES` |
| `exif_hints` | 短絡用の要約（SS、F値、露出補正等。実装で抽出） |

### 5.3 ShortlistStageResult

各段の入出力スナップショット。

| フィールド | 説明 |
|------------|------|
| `session_id` | セッション |
| `stage` | `M1` \| `H1` \| `M2` \| `H2` \| `M3` \| `H3` \| `W` |
| `input_ids` / `output_ids` | 段に入った／出た source または work |
| `excluded_ids` | この段で除外されたもの（H1 回収の対象） |
| `notes` | 任意 |

### 5.4 ShortlistCandidate

| フィールド | 説明 |
|------------|------|
| `source_id` / `session_id` / `stage` | 参照 |
| `priority` | 小さいほど優先 |
| `tier` | `core` \| `maybe` \| `margin`（余白枠）\| `excluded` |
| `status` | `proposed` \| `kept` \| `rejected` \| `recovered` |
| `reason_brief` | 短い提案理由（見るだけ可） |
| `antenna_peaks` | 相対熱量の要約（軸キーと相対順位／バンド。絶対★必須としない） |
| `mood_tags` | 内部用情緒タグ（任意表示） |
| `signals` | 実装用信号 |

状態遷移:

```text
proposed --> kept | rejected
excluded --> recovered --> kept
kept --> rejected
rejected --> kept | recovered
```

### 5.5 Work（ペア＋現像）

1つの確定コマ（`stem`）に対し、Works 配下に次が揃い得る。

| 役割 | ファイル規則 | 説明 |
|------|--------------|------|
| 撮って出し | `{stem}.jpg` / `{stem}.JPG` / `{stem}.HIF` / `{stem}.heif` 等 | カメラからのプレビュー。サフィックスなし |
| RAW | `{stem}.ORF` / `{stem}.RAF` 等 | メーカー別。拡張子一覧は実装で単一ソース化（最低限 ORF/RAF） |
| RAW 現像 JPEG | **`{stem}_dev.jpg`** | DxO 等の書き出し。サフィックス **`_dev` 固定（確定）** |

| フィールド | 説明 |
|------------|------|
| `id` / `source_id` / `stem` | 作品ID・元・ベース名 |
| `sooc_path` | 撮って出しパス（任意・欠ける場合あり） |
| `raw_path` | RAW パス（任意・JPEGのみのコマもあり得る） |
| `dev_path` | `{stem}_dev.jpg`（現像後に埋まる） |
| `critique_image_path` | 対話痕跡に使う1枚（§6.8 の優先順で決定） |
| `user_comment` / `keywords` | 任意 |
| `created_at` | 作成日時 |

旧来の単一 `rendition` 枚挙は、実ファイルの三系統に置き換える。  
「JPEG 補正のみ」を別ファイルで持つ場合は、第一波では `_dev.jpg` に載せるか撮って出し扱いとし、必要なら後続で `{stem}_edit.jpg` を足す。

**週次でもイベントでも、H3 確定後は W でペアコピー（と現像待ち）を行う。**

同一フォルダに同名 `.jpg` は置けないため、「撮って出し」と「現像」は **`_dev` サフィックスで必ず区別する**。不要 JPEG の削除は必須にしない。

### 5.6 DialogueTrace

| フィールド | 説明 |
|------------|------|
| `work_id` / `card_path` / `note_path` | 紐づけ |
| `critique_image_path` | 実際に講評した画像（通常は `dev_path` または撮って出し） |
| `mode` | `compact` \| `full` |
| `lens` | `self` |
| `ai_wording` / `user_reaction` | 言語化と反応（`agree` \| `disagree` \| `unset`） |

生成: 既存 `critique_engine` → `generate_critique_card` → `DesktopLogManager` を **`critique_image_path` の1枚** に対して実行。`_lumina/works/*.json` にパスを必ず記録。

### 5.7 DecisionDelta

| フィールド | 説明 |
|------------|------|
| `session_id` / `library_unit_id` / `stage` | 段ごと、または `stage=session` で全体 |
| `proposed_*` / `kept_ids` / `rejected_ids` / `recovered_ids` | 差分 |
| `completed_at` | 時刻 |

R1′-A では保存と参照ができれば合格。学習への利用は R2′。

### 5.8 ShortlistSession

| フィールド | 説明 |
|------------|------|
| `id` / `library_unit_id` | 識別 |
| `current_stage` | いまの段 |
| `target_keep_count` | 最終目安（週 20／イベント 40 等） |
| `status` | `running` \| `awaiting_human` \| `awaiting_develop` \| `completed` \| `cancelled` |
| `stage_results` | ShortlistStageResult の列 |
| `created_at` | 開始 |

`awaiting_develop`: ペアコピー済みで、`_dev.jpg` 待ち／対話痕跡未実行の状態。

## 6. 段階短絡フロー（R1′-A の中核）

オーナー案（機械選別／Lumina 観点／多様性）を骨格とし、取りこぼし防止のため人ゲートと相対熱量を加える。

```text
単位選択 → スキャン
  → M1 機械選別（保護つき消去法）
  → H1 人の回収ゲート（推奨・取りこぼし防止の要）
  → M2 Lumina アンテナ（相対熱量・厚い候補）
  → H2 人の確認（任意）
  → M3 多様性・余白・執着（編集者調整）
  → H3 対話確定（言語化を見る／kept）
  → W  ペアコピー（撮って出し＋RAW）→（Works 内で現像）→ 対話痕跡
  → DecisionDelta 保存・セッション完了
```

### 6.1 段の定義

| 段 | 週の目安 | イベントの目安 | 性質 | 主なアクション |
|----|----------|----------------|------|----------------|
| **M1 機械** | 200→≈100 | 400→≈200 | 消去法＋保護 | 手ブレ・ピンボケ等の明らかな失敗を除外。低速シャッター・開放・意図的アンダー等は **意図の保護**。連写・類似は「光のコントラストが鋭い1枚」へ代表圧縮（手法は実装詳細） |
| **H1** | — | — | 人 | **機械除外リストを見直し回収**。第一波ではこのゲートを推奨（スキップ可にする場合も除外一覧は残す） |
| **M2 アンテナ** | 100→≈50 | 200→≈100 | 相対熱量 | 既存5軸のアンテナ反応を軽量推定。セッション内相対で上位を厚く残す。`core`+`maybe`。**★5必須などの絶対閾値は禁止** |
| **H2** | — | — | 人 | 任意。明らかな不一致の除外／戻し |
| **M3 多様性** | 50→≈20 | 100→≈40 | 編集者 | 情緒タグ等で偏りを抑え、「余白（margin）」を混ぜる。撮影者の執着・癖が強いコマは優先残存 |
| **H3** | ≈20 確定 | ≈40 確定 | 対話 | reason_brief を見る／反応。最終 kept / reject / recover |
| **W 作品** | 確定分 | 確定分 | 保存 | §6.8 のペアコピー→現像→痕跡 |

### 6.2 3観点との対応

| 観点 | 担当 | 原則 |
|------|------|------|
| 機械選別 | M1＋H1 | 失敗は落とす。EXIF に残る表現意思は落とさない |
| Lumina Notes 観点 | M2＋H2 | 評価ではなくアンテナ熱量。絶対★ゲート禁止（`PHASE_D_FINDINGS.md`） |
| 多様性調整 | M3＋H3 | 余白・偏り是正・執着優先。★5揃いの息苦しさを避ける |

### 6.3 M2 で使う5軸（既存レンズに揃える）

| 内部キー | 表示名 | 短絡での見方（熱量） |
|----------|--------|----------------------|
| `framing` | 眼差の輪郭 | 枠取り・導線・構造の鋭さ |
| `sensitivity` | 感情の陰影 | 光・反射・グラデーションの鋭敏さ |
| `story` | 物語の気配 | しぐさ・佇まい・前後の時間の予兆（無人物の擬人化禁止） |
| `technical` | 表現の意図 | 露出・被写界深度など表現意思の読み取りやすさ |
| `sense` | 感性の兆し | 定型から外れた執着・癖の強さ |

選抜は「どれか絶対★5」ではなく、**ピーク軸の相対順位**や **複数軸の共鳴**、および `maybe` の厚みで行う。

### 6.4 M1 で保護する意図の例（閾値は実装詳細）

仕様上、少なくとも次を「保護候補」として扱えること。

- 低速シャッター（手ブレ足切りと衝突しうるが、表現意思として保護優先を検討）
- 開放寄り絞り
- 意図的アンダー（マイナス補正。RAW のハイライト保護を含む）

### 6.5 エラー方針

- 1枚の失敗でセッション全体を止めない。
- オリジナルの削除・上書きは行わない。
- 外部現像ファイル欠損は当該作品のみ保留。

### 6.6 再実行

- 同一 LibraryUnit でやり直せる。
- 既存 Work は上書き確認（黙って消さない）。
- 段の途中保存から再開できることが望ましい（第一波の努力目標。最低でもセッション単位のやり直しは必須）。

### 6.7 コスト分離

- M2/M3 は軽量パス。全枚フル講評（Phase2）は短絡中に走らせない。
- フルカードは **W で `critique_image_path` が決まったあと**。

### 6.8 W 詳細: ペアコピー → 現像 → 対話痕跡

オリジナル側の前提:

- カメラからコピーした、**同じ `stem`** の撮って出し（`.jpg` / `.HIF` 等）と RAW（`.ORF` / `.RAF` 等）が同居していることが多い。

手順:

```text
[W1] 確定 stem ごとに、存在する撮って出しと RAW を Works へコピー
     （片方しか無い場合はその片方だけ。オリジナルは触らない）
        ↓
[W2] ユーザーが Works 内の RAW を DxO 等で現像し、
     出力名を {stem}_dev.jpg として Works に保存
        ↓
[W3] critique_image_path を決定（下記優先順）
        ↓
[W4] その1枚に対してカード・ノート・ログを生成／更新
```

`critique_image_path` の優先順（名前規則で判別。削除は必須でない）:

1. `{stem}_dev.jpg` があればそれを使う（現像優先）  
2. なければ撮って出し（`.jpg` / `.HIF` 等）  
3. RAW のみでプレビューも `_dev` も無い → 痕跡生成は保留（`awaiting_develop`）

DxO 等の書き出し設定は、**`{stem}_dev.jpg`** になるよう運用で合わせる（仕様上の契約）。

Works 内の例:

```text
_lumina/works/
  IMG_0001.jpg          # 撮って出し
  IMG_0001.ORF          # RAW
  IMG_0001_dev.jpg      # RAW 現像
  IMG_0001.json         # メタ（各パスと critique_image_path）
```

## 7. 候補提示・言語化

- H3（および必要なら M2/M3 レビュー）で `reason_brief` を見せる。見るだけでもよい。
- ユーザーは修正してもしなくてもよい。「そう思う／そうではない」反応を任意で残せる。
- オリジナルを人が確定する前にディスクから消さない（除外はリスト上の状態）。

## 8. UI 方針（デスクトップ）

### 8.1 配置

- 現行講評バッチ GUI（`app_gui.py`）は維持。
- 深い輪は別モード／別導線。新フレームワークへの全面移行はしない。

### 8.2 画面の仕事（R1′-A）

1. LibraryUnit 選択  
2. 段の進捗（M1…H3…W）  
3. **H1: 機械除外の回収リスト**  
4. 候補レビュー（サムネ、理由、tier、kept/reject/recover）  
5. 作品取り込み（ペアコピーの実行、現像待ち一覧、`_dev.jpg` 検出、痕跡生成）  
6. セッションサマリ  

ダッシュボード化しない。確認リストと一枚ずつの対話が主。

### 8.3 設定

- `~/.photo_ai_config.json` の既存キーは壊さない。
- 深い輪用キーを追加（最後の LibraryUnit、目安 keep 数、カードテーマ等）。

## 10. 受け入れ条件（R1′-A）

| # | 条件 | 合格の目安 |
|---|------|------------|
| A1 | 月／イベント単位を選べる | イベント命名規則どおり |
| A2 | M1→H3 の段階が追跡できる | 各段の残数／除外が見える |

| A4 | M2 が絶対★ゲートに依存しない | ★5必須で落とさない |

| A6 | 週次でもイベントでも、確定分の撮って出し＋RAW を Works へペアコピーできる | オリジナル不変。ORF/RAF 等 |
| A6b | `{stem}_dev.jpg` を対話対象として優先できる | 無ければ撮って出し。RAWのみなら保留 |
| A7 | 作品にカードとノートが紐づく | works JSON から `critique_image_path` 経由で辿れる |
| A8 | 段またはセッションの DecisionDelta が残る | 後から比較できる |
| A9 | 1枚失敗で全体停止しない | ログに残り継続 |
| A10 | 既存講評バッチが回帰しない | 従来どおり動く |

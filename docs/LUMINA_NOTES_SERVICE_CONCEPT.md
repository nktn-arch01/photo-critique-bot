## 1. 一文で言うと

Lumina Notes は、写真の採点・整理ツールではない。  
**撮った写真と対話し、気づき（AWARENESS）を積み、未来の自分が過去の自分から新しい問いを受け取れる**ようにする伴走サービスである。

ブランド原則（既存レンズ定義と同型）:

- **評価ではなく理解**
- **答えではなく対話**

AI の役割は決定者ではなく、**伴走者**。最終の「残す／残さない」は撮影者。

---

## 2. 求める姿（北極星）

中心にあるのは、写真を残すことから始まり、写真を見返し、言葉にし、もう一度写真を見る。その往復の中で、これまで見えていなかったものに出会っていくこと。

1. **その日のうちに**: 撮って帰ってきたら、選ぶ・見返す。それを繰り返して蓄積する。  
2. **あとから**: 未来の自分が過去の自分を振り返り、**新しい気づき**を得る。

成功指標は「何枚減らせたか」そのものではない。

- 写真との短い対話が習慣になっていること
- 対話の痕跡が、後の自分に新しい AWARENESS を返すこと
- その結果として、次の撮影への問いが残ること

```text
[速い輪: 当日〜習慣]
  撮る → 少数を選ぶ／見返す → 痕跡を残す → 次の撮影への問い
        ↓ 蓄積
[深い輪: あとから]
  痕跡とライブラリを読み返す → 新しい気づき → 章／冊子 → 次の問い
```

---

## 3. サービス構造: 二速度（E1）

表の顔は「対話」、裏方に「選別・作品・章」を置く。旧来の Cull → Export → Book だけを正面にしない。

### 3.1 速い輪（当日〜毎日）

| 項目 | 方針 |
|------|------|
| 目的 | その日のうちに選ぶ／見返すを、重荷にせず続ける |
| 分量の目安 | **20枚 → 1枚／日**（スマホ派・デジカメ派） |
| 行為 | 選ぶ・見る・言葉を残す・次の撮影への問いを受け取る |
| 成果の本体 | 作品化の強制ではなく **対話痕跡**（コメント／キーワード／軽量カード等） |
| 短絡の意味 | 「良い写真ランキング」ではない。「今日立ち止まれそうなコマ」の提案。迷いは優先度付きで多めに出してよい |

言語化について: 自分で一言考えて残すのは難しいことが多い。**AI が言語化を支援**し、ユーザーはそれを見るだけでもよい。納得してもしなくても「そう思う／そうではない」という反応を引き出すところから、気づきと対話が生まれる。ユーザーは AI の文を修正してもしなくてもよい。

> 撮って帰ったら、今日の数枚と対話して寝る。

### 3.2 深い輪（週・月イベントの振り返り）

| 項目 | 方針 |
|------|------|
| 目的 | 未来の自分が過去を読み直し、新しい気づきを得る |
| 分量の目安 | **週 200 → 20**、**月／イベント 400 → 40**（およそ 1/10） |
| 行為 | 候補提案→人の確定→作品化→カード／ログ紐づけ→振り返り（章／レポート等） |
| 成果 | 対話型の章（当面は画面・PDF）。加えて蓄積ログの分析レポート。印刷・入稿は後続 |
| 入口 | 範囲指定（月・年・キーワード・イベント）／種写真からの物語 |

> あとから開くと、過去の自分の眼差しが、今の自分に新しい問いを返す。

### 3.3 二つの輪の接続（製品の芯）

- 速い輪がないと、深い輪は冷たいアーカイブ整理に戻る。
- 深い輪がないと、速い輪はその場限りのチャットで消える。
- **痕跡（コメント、キーワード、カード、問い、提案と確定の差分）が未来の振り返りの素材になる**ことを必須とする。

## 4. 想定ユーザー（3類型）

共通の縮約感はおおむね **約 1/10**。違いは頻度・深さ・画像状態。

| 類型 | 速い輪 | 深い輪 | 作品の画像状態（当面） | 主チャネル |
|------|--------|--------|------------------------|------------|
| スマホ派 | **毎日** 20→1。JPEG/HEIF 撮って出し | 必須ではない（痕跡の振り返り） | 撮って出し | モバイル／LINE に近い面 |
| デジカメ派 | **毎日** 20→1 | 週 200→20 ＋ 月イベント 400→40 | 撮って出し／JPEG補正 | 速い輪＋デスクトップ |
| ミラーレス派 | 毎日は薄くてよい（帰宅後予選は任意） | **週 200→20 ＋ 月イベント 400→40 が主** | 撮って出し／JPEG補正／RAW現像JPEG | デスクトップ |

類型ごとの一文:

- **スマホ派**: 毎日1枚と対話して溜め、あとから眼差しの変化を読む。  
- **デジカメ派**: 毎日の1枚で感覚を温め、週とイベントでまとめて作品にする。  
- **ミラーレス派**: 週とイベントの深い選別・現像・章づくりが中心。

### 4.1 最初に届ける類型: ミラーレス派

| 項目 | 方針 |
|------|------|
| 理由 | オーナー自身がユーザーとして日常テストし、フィードバックを回す |
| 第一優先 | **深い輪**（週／月イベント） |
| 主チャネル | デスクトップ（現行の月・イベントフォルダ運用の延長） |
| 作品 | 当面は外部アプリ（DxO 等）で作った成果を取り込む。自前 RAW エンジンは作らない |
| 速い輪（毎日 20→1） | 構想には残すが **後続** |
| スマホ／デジカメ派 | 構想上は維持。実装第一波では必須にしない |

## 5. ライブラリの置き場

当面はローカル。将来はクラウドアルバム入力アダプタを足せる形にする（最初からクラウドを SoT にしない）。

| 単位 | 例 | 規則 |
|------|-----|------|
| 月 | `.../202608/` | 親フォルダ名 **`YYYYMM`** |
| イベント | `.../202608/20260810_京都旅行/` | **`YYYYMMDD_短い名前`**（開始日＋`_`＋名前） |
| 月直下のバラ | `.../202608/*.jpg` | イベントに属さない日々の蓄積 |

イベント名の詳細:

- 複数日の旅行でも開始日1つでよい。
- スペースなし。日本語可。記号は `_` と `-` 以外を避ける。
- このパターンに一致するサブフォルダだけをイベント単位として扱う。
- 一致しないサブフォルダはイベント扱いしない（必要ならリネームで寄せる）。
- UI／章の表示名は `_` 以降を使う。

```text
Photos/
  202608/
    IMG_....JPG
    20260810_京都旅行/
      ....JPG
    20260822_海辺の午後/
      ....JPG
```

## 6. 深い輪に含まれる機能（旧 Track1 の再配置）

初期要望の1〜5は、バラバラの機能ではなく深い輪（と将来の速い輪）に再配置する。

| 要望の要約 | E1 での位置 |
|------------|-------------|
| 大量からの候補短絡 | 深い輪の候補検索／提案（★だけで絞らない）。速い輪では当日の少数提案 |
| 作品として別保存 | 主に深い輪。撮って出し／補正／RAW現像JPEG。当面は外部成果の取り込み |
| コメント・キーワード＋カード／ログ | 対話痕跡。深い輪では既存のカード・分析ログを活用。速い輪は軽量でも可 |
| 月・年・キーワード等からのフォトブック | 深い輪の振り返り章（当面は画面・PDF、印刷は後続） |
| 蓄積ログの分析レポート | 深い輪の振り返り手段のひとつ。フォトブック以外も想定。分析は NotebookLM など **外部連携** を想定 |
| 種写真からストーリー＋不足画像 | 深い輪の強力な入口（「この数枚が気になる」から始める） |

### 6.1 短絡の進化

- 基本は **AI提案 → 人が確定**。
- 初期は迷い候補を優先度付きで多めに出してよい。
- 使い込むほど提案と確定の差分が縮む方向へ進化する（採点精度競争ではない）。
- 現行の揺れる ★ だけを唯一根拠にしない（`PHASE_D_FINDINGS.md`）。

### 6.2 作品と現像

- オリジナル庫は壊さない。作品は別保存。
- **当面**: 外部で作った撮って出し／補正／RAW現像 JPEG を取り込む。
- **将来**: 外部アプリ・サービス連携で補正／現像フローを起動・取り込む（自前現像エンジンは作らない）。

### 6.3 振り返りの出口（章・レポート）

- **フォトブック（章）**: 当面は自分で読む／振り返る対話冊子（画面・PDF）。印刷・業者入稿は後続。ブックは目的そのものではなく、対話ノートの章を綴じた結果、と位置づける。
- **分析レポート**: 蓄積したログデータを分析し、深い輪の振り返りに使う。分析エンジンは自前必須とせず、**NotebookLM など外部連携**を想定する。

## 7. 既存システムとの関係

| 面 | 方針 |
|----|------|
| 第一波 | デスクトップ中心。現行の講評エンジン・カード・`DesktopLogManager` を対話痕跡レイヤとして再利用 |
| LINE | 単枚対話の入口として維持。速い輪（スマホ派）拡張の候補だが第一波の必須ではない |
| レンズ | `lens=self`（本人対話）。`audience` は将来枠のまま |
| スコア | アンテナのスナップショット。深い輪の唯一の選別キーにしない |

---

## 8. 意図的にやらないこと

- サービス正面を「AIカリング／枚数削減ツール」として打ち出すこと
- 当日にフル現像・フルブックまで強制すること
- 痕跡なしの振り返りだけを主経路にすること
- 自前 RAW 現像エンジンの内蔵
- 初日からクラウドを主ライブラリ（SoT）にすること
- 初日からマルチテナント／課金を必須にすること
- AI が最終選別まで無人完了すること

## 9. Ripeness（届け順・ミラーレス派先行）

| ID | 内容 | 対象 |
|----|------|------|
| **R1′** | 深い輪: 週／イベントの提案→確定→作品取り込み→カード／ログ→振り返り（章／レポート） | ミラーレス派・第一波 |
| **R2′** | 提案と確定の差分が、次の提案をセンスへ寄せる | 同上 |
| **R3′** | 種から物語・不足コマ提案 | 深い輪の強化 |
| **R4′** | 速い輪（毎日 20→1） | スマホ／デジカメ、ミラーレスの帰宅後予選 |
| **R5′** | クラウド入力、外部現像連携、NotebookLM 等の分析連携、印刷、オープン化・収益化 | 拡張 |

北極星の「当日の繰り返し」は捨てない。ただし **最初の実用品は、オーナーが日常で回せる深い輪（R1′）から入る**。
